# 生成后验收（移动端）

依据本 Skill 生成或修改的页面、页面模式、组件预览，交付前**必须**按本文件验收。只读代码、看截图都发现不了溢出、热区、字号、资源缺失这类问题，必须在浏览器里实际渲染并读取计算值。

## 1. 自动检查（必做）

```bash
node scripts/verify-page.cjs <页面.html> [--widths 375,320,768] [--container h5|webview|miniprogram] [--shots <截图目录>]
```

- 默认检查 3 个宽度，各代表一类风险（分档见 `h5-sizing-and-adaptation.md`）：
  - **375**：设计基准，核对与 Figma 一致；标准档 360–449 为纯等比缩放，375 通过即覆盖。
  - **320**：小屏档最窄端，检查溢出、挤压、字号下限与 `@media (max-width:359px)` 兜底。
  - **768**：大屏代表（平板竖屏、折叠屏展开、企业微信 PC 窗口），尺寸已封顶、宽度流式拉伸，检查背景与固定栏撑满、内容不被拉得过宽、≥600 的多列规则。
- 目标设备有其它宽度时追加（如 `--widths 375,320,768,414`）；确定只在手机上运行时可改为 `--widths 375,320`，并在报告中说明。
- 本地文件默认通过内置静态服务以 http 打开（根目录为包含 SKILL.md 的目录）。交付方式是“双击 HTML 离线打开”时，再加 `--file` 单独验收一次。
- `--container` 按实际运行容器填写。`miniprogram` 指小程序原生页面，会跳过输入字号与 viewport 检查。
- 依赖 Playwright。有「阻断」项时退出码为 1，修复后重新运行，直到阻断为 0。

### 检查项与判定

| 检查 | 级别 | 判定 |
| --- | --- | --- |
| 页面横向溢出 | 阻断 | `scrollWidth > clientWidth` |
| 元素超出屏幕 | 阻断 | 非固定定位、且不在滚动容器内的元素超出视口 |
| 字号 < 10px | 阻断 | 任何可见文字 |
| 缺少可访问名称 | 阻断 | 按钮、链接、页签、开关、输入框没有文字、aria-label 或关联标签 |
| 图片缺 alt | 阻断 | `<img>` 没有 alt 属性（装饰图写 `alt=""`） |
| 弹窗缺标题关联 | 阻断 | 可见的 `role=dialog` 没有 aria-labelledby / aria-label |
| 图标不是图标库资源 | 阻断 | `--gj-icon` 不指向 `assets/icons/` 下的登记资源 |
| 输入字号与 viewport | 阻断 | H5 / web-view 有输入框字号 < 16，但 viewport 没有 `maximum-scale=1` |
| 脚本错误、资源加载失败 | 阻断 | 控制台报错、请求失败或 4xx / 5xx |
| 未设置盒模型 | 提示 | body 不是 `border-box`，带内边距的组件可能溢出 |
| 文字被裁切无省略号 | 提示 | 叶子文字溢出且没有 `text-overflow: ellipsis` |
| 字号 10–11px | 提示 | 只允许辅助文字、Small 标签、底部导航标签；320 宽下正文不低于 12（`h5-small-screen.md`） |
| 热区 < 44 | 提示 | 含 `::after` 扩展后仍不足；行内文字链接、已批准的密集列表例外（如星级分布行高 34）可保留 |
| 按钮图标与文字颜色不一致 | 提示 | `.gj-m-button` / `.gj-m-text-button` 内的图标颜色与文字颜色不同 |
| 同一行按钮高度不一致 | 提示 | 同一容器、同一行里有不同高度的按钮 |
| 页面级间距不在阶梯上 | 提示 | 页面自定义容器的 gap / padding 按 375 折算后，不在 4/8/12/16/20/24/32/40/48 上；安全区、底栏预留这类计算值可忽略 |
| 金额 / 指标未用等宽数字 | 提示 | 指标数值没有 `tabular-nums` |

另外运行 `node scripts/embed-icons.cjs <页面> --check`：页面必须已内嵌图标（未内嵌或页面改动后未更新时退出码 1，运行不带 `--check` 的同一命令即可修复）。内嵌后图标为真正的 SVG，Figma「网页导入」才能保留图标；视觉与交互不变。

## 2. 交互实测（必做）

自动检查只看静态状态。页面实际支持的交互需要逐个触发，并在**每个状态下**重新跑一遍自动检查，或至少截图复核：

- **选择与切换**：页签、分段、筛选、单选、多选、开关。
- **输入**：聚焦、输入、清除、校验错误、计数；有固定底栏时检查键盘弹起后的遮挡（`keyboard` 组件说明）。
- **浮层**：打开、关闭、遮罩、Esc；锁定背景滚动；关闭后焦点回到触发控件。
- **异步状态**：加载（骨架屏）、空状态、错误与重试；空状态在受影响区域内居中。
- **长内容**：长标题、长值、多行错误、较大金额；检查截断、换行和数字对齐。

## 3. 人工核对（必做）

逐条对照 `references/page-rules.md`，重点核对自动检查无法判断的项：

- **卡片层级**：同一页面同一起始层级只用一种承载方式；0 级卡片首个贴住导航（PR-016）。
- **间距**：按视觉边缘量，容器留白只算一次；卡片标题到首行、末行到卡片底均为 16（PR-007 / PR-013）。
- **组件选档**：页签、分段控制、标签尺寸与风格层级（PR-001 / 002 / 005 / 012）；卡片内多选用按钮组合（PR-009）。
- **位置**：卡片操作在右下角（PR-017）；顶部筛选区高度、提示单行（PR-018）。
- **大屏（768）**：背景、导航、固定栏随容器撑满；≥600 时卡片列表、宫格等按 `h5-sizing-and-adaptation.md` 改多列，单列内容限制最大宽度，不被拉成整屏宽的长条。
- **导航与容器**：首页入口最左、个人入口最右；小程序原生页面不自绘导航；二级页面不显示底部导航。
- **左右并列信息**（PR-024）：按真实换行核对两侧行数，优先一致；不一致时优先左多右少，避免右侧更多行。375 / 320 / 768及长名称、大金额均需检查，不能只数DOM子元素。
- **信息层级**：标题、关键数据、主操作、辅助信息的阅读顺序符合业务优先级。

### 参考稿结构验收（PR-033 / PR-034）

生成前保存区域树与边界清单，生成后独立对照：区域数量和顺序、字段、操作入口、标题/状态归属、分割线/背景边界的存在与通栏/缩进范围。记录每项对应的原稿区域和实现选择器，差异注明来源及用户授权。截图参数与运行校验通过不等于结构一致。隐藏信息保持待确认。

## 4. 交付报告模板

```markdown
## 验收报告：<页面名>
- 运行容器：小程序原生 / H5 / web-view
- 实测宽度：375、320、768（及目标设备宽度）
- 自动检查：阻断 0 项；提示 N 项（逐条说明保留理由或已修复）
- 交互实测：<操作 → 结果>，每个状态下检查结果
- 人工核对：page-rules 逐条结论（不适用的写“不适用”）
- 与参考稿的差异：<改动与理由>
- 待确认：<问题、已查资料、对产出的影响>
- 未验证：<真机安全区、真实键盘、目标设备等>
```

报告只写实际运行过的结果。没有运行或无法覆盖的项目写进「未验证」，不写成已通过。
